# Architecture implementation status

Implemented on 2026-09-26. React, TypeScript and Vite remain the UI stack. This implements the main ownership and persistence changes from [the architecture review](architecture-review.md); it does not claim every proposed optimization or host integration is finished.

## Delivered

- **Shared connections:** one registry across Notebook and Investigation; serialized, awaited mutations; storage errors remain visible; connection edits get durable revisions; unreadable credentials preserve their connection metadata and original stored secret references.
- **Execution ownership:** requests snapshot their inputs and connection, belong to a document and cell, and cannot overwrite a newer run or resurrect deleted documents. Tracking follows its originating notebook. Browser/Electron/Tauri HTTP and gRPC use deadlines and cancellation. Federated execution is limited to four concurrent requests and skips canceled queued requests. Notebook and Investigation results identify the originating request and show when inputs or selected connection settings have changed. Federated progress is owned by each cell and updates as each cluster finishes.
- **Document domains:** pure document creation/conversion/reducer functions, explicit type conversion, protected identities, validated reordering, one document store and save coordinator. Compatibility APIs delegate to the same domain operations. Investigation creation and cell mutations also use pure domain functions; rename changes now pass through its save coordinator.
- **Durable workspace:** versioned IndexedDB documents and separate result records; transactional revision checks reject stale writes/deletes from another window. Failed saves retain editable drafts and offer retry. Coalesced writes are serialized per document, paused during deletion, and do not let one document's success hide another's failure. Unchanged result bodies are not reserialized with each document edit. Normal startup reads document content without saved result bodies. Results load when their Notebook or Investigation is selected (including restored selections), and up to two inactive, clean result documents per feature remain cached in memory. Least-recently-used inactive results are released and reload from IndexedDB on selection. Active documents, running executions, pending writes, and failed saves are protected; persisted results are retained. This is a document-count bound, not a byte limit. Loading groups and drafts does not read results. One-time legacy migration still fully reads outputs to verify them. Storage rejects writes of documents whose results have not been loaded, preventing accidental result deletion.
- **Opening saved documents:** concurrent selections share reads and only the latest selection becomes active. The current document stays usable while another opens. Failed reads expose retry; missing results or changed cross-window revisions preserve stored records. Late reads cannot resurrect deleted documents. Provider loading starts in effects and survives React StrictMode cleanup/resume without duplicate reads.
- **Migration:** validate legacy records, copy missing records, verify read-back, then mark complete. Interrupted migrations resume, conflicting or malformed data stops startup visibly, and the old localStorage records are retained. This recovery copy is a historical snapshot, not a rollback of edits made after migration.
- **Other features:** Investigation has its own persistent document/run store. Pipeline and ISM drafts use the same durable repository and survive feature unmounts. ISM analysis is an application workflow with a short debounce. Pipeline evaluation ignores superseded/unmounted runs and catches asynchronous simulation errors.
- **Platform boundary:** services call a shared typed runtime boundary instead of each choosing a host. Separate browser, Electron and Tauri adapters are injectable and selected once at app bootstrap. Native HTTP responses use standard Response semantics and normalized headers. Tauri secrets use real OS Keychain references, reject the old Base64 placeholder, and fail visibly when unavailable. Secret references are reused for unchanged credentials; replaced references are removed after metadata commits, and newly created references are cleaned up after failed commits. Native writes reserve an opaque reference before storing a secret and verify it by read-back. A reference-only journal recovers interrupted writes and retries cleanup after restart, under the cross-window connection lock and only after validating all committed metadata. Cleanup is deferred when Web Locks are unavailable; the app never enumerates unrelated vault entries. This is the first release, so credential migration is not required or implemented.
- **Editor integration:** shared run shortcuts replace overlapping command/key handlers, reject key repeat and composition events, and dispose with the editor. Completions share the same resource ownership helper. ISM and pipeline diagnostics bind to their mounted Monaco instance, including diagnostics produced before mount and cleanup on model changes. All editors now share theme selection and unique mounted-model identities, dispose their models on unmount, and avoid the wrapper’s unbounded view-state cache. Document switches remount editor lists. Monaco 0.57 and its editor/JSON workers are bundled locally and loaded lazily; desktop editing no longer needs the wrapper’s CDN loader.
- **Desktop close protection:** closing a Tauri or Electron window, including Quit, cancels document executions and awaits document, draft, and connection saves. Repeated close requests share one flush. Failed or stalled saves leave the window open with an error and allow retry. Browser unload warns while writes are pending. Forced termination and crash recovery remain separate concerns.
- **Local pipeline simulation:** Data Prepper evaluation uses the existing TypeScript simulator. It runs in a dedicated local worker in supported hosts; Cancel, input changes, replacement runs and unmount terminate the owning worker. A synchronous local fallback remains for hosts without Worker support. Docker mode, backend probes, port-3001 adapters and desktop proxy commands were retired after clarification of the intended workflow. Compose still pins OpenSearch 3.8.0 and Data Prepper 2.16.0 for independent manual testing. Pipeline imports validate a complete candidate before applying a single draft update; valid legacy partial imports remain supported.
- **Feature boundaries:** Notebook, Investigation, Data Prepper, and ISM now own their UI and React bindings under their feature directories. The app composes the persistent Notebook and Investigation providers; Notebook no longer mounts another feature. Shared connection controls subscribe directly to the connection registry. ESLint rejects cross-feature imports, feature-to-app imports, shared-UI-to-feature imports, and UI dependencies from domain, application, and state modules. Boundary probes confirmed these restrictions compose rather than overwrite one another.
- **Loading/rendering:** separate lazy feature bundles, memoized cell editor content, focused state hooks, and lint rules separating the extracted domain/application layers from UI and platform dependencies. Notebook menu actions are keyboard-accessible buttons. Investigation editor rows now use focused subscriptions and stable memoized props; editing or receiving progress in one cell does not rerender its sibling editor.

## Integration status

The earlier claim that port 3001 blocked the plan was incorrect: the intended workbench workflow is local simulation. That unused execution path has now been removed. No Data Prepper backend is required and none will be built for this plan. Live OpenSearch multi-cluster checks remain unverified. Native Windows Credential Manager and Linux Secret Service integration, packaging, and close behavior require their respective OS environments; this workspace has only macOS ARM64 and its Rust target. That is the current native-validation blocker. macOS smoke checks are recorded above and do not establish Windows/Linux parity. No service containers were started or modified during this continuation.

## Simulation measurement

A local Vitest measurement used JSONL events with `add_entries` and `rename_keys`, validating output counts on all five samples at each size. The observed synchronous durations were:

| Events | Duration range |
| --- | --- |
| 100 | 0.9–3.3 ms |
| 1,000 | 3.9–6.0 ms |
| 10,000 | 35.2–36.6 ms |
| 50,000 | 170.5–183.9 ms |

These are local test-harness timings, not browser latency or packaged-host benchmarks. The 50,000-event blocking cost justified moving simulation into a worker; worker startup, input/output copying, source validation and output rendering still need browser profiling. The opt-in fixture is `src/__tests__/property/simulationTiming.property.test.ts`; run with `MEASURE_SIMULATION=1 npx vitest --run src/__tests__/property/simulationTiming.property.test.ts`. It has no timing threshold and is skipped in ordinary regression runs.

## Remaining implementation work

- Feature UI/context migration is complete. Older service/type modules remain at their established paths; further relocation should follow ownership changes, not directory churn.
- No older-credential migration is planned for the first release. Verify the configured Windows Credential Manager and Linux Secret Service backends on native hosts. Journaled cleanup deliberately defers without cross-window locking; clearing app storage also loses its journal.
- Results now have bounded inactive-document caching. Byte budgets and an explicit user-facing disk-retention policy remain future work; no saved outputs are silently deleted.
- Measure large-notebook editor latency, ISM analysis, and browser validation/output rendering before adding further workers or virtualization. File-service adapters and remaining broad subscriptions remain incremental work; shared editor identity/theme ownership and Investigation editor isolation are implemented.
- Continuous autosave, controlled-switch flush, visible failures, and desktop close negotiation are implemented. Async saving still cannot guarantee the final keystroke survives forced termination. Crash-journal recovery remains future work.

Pre-existing working-tree changes were preserved. Implementation phases are recorded in Git at the user’s request. No pull request, deployment, or signed release was created.
